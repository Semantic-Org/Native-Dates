تنسّق Native Dates عبر بيانات `Intl` المدمجة في محرّك JavaScript، فتعمل كل لغة ونظام كتابة وقاعدة جمع ونظام تقويم من دون تنزيل ملفات إعدادات محلية.

يعتمد موضع ضبط الإعداد المحلي على بيئة التشغيل؛ اختر المستوى الذي يطابق طريقة عمل تطبيقك:

- **الإعداد الافتراضي لبيئة التشغيل** عندما يتبع تطبيق المتصفح إعدادات نظام القارئ
- **الإعداد العام عبر [`configure()`](/api/configure/)** عندما يوفّر تطبيق العميل مبدّل لغة خاصًا به أو يستهدف إعدادًا محليًا ثابتًا
- **الإعداد المحلي على مستوى القيمة عبر [`locale()`](/api/date-time/#locale)** عندما ينسّق الخادم لكل طلب على حدة أو تحمل سلسلة استدعاءات إعدادها المحلي الخاص
- **التجاوز لاستدعاء واحد عبر [`format()`](/api/date-time/#format)** عندما تحتاج تسمية واحدة إلى تقويم آخر أو لهجة إقليمية مختلفة

## العمل دون إعداد في المتصفح

عندما لا يُضبط إعداد محلي ولا يُمرّر، تستخدم كل خاصية `.text` وكل استدعاء `format()` والنطاقات والمدد الزمنية ودوال الأسماء المساعدة الإعداد المحلي النشط في بيئة التشغيل.

لا تحتاج تطبيقات المتصفح أحادية المستخدم التي تتبع لغة نظام القارئ إلى أي إعداد:

```js
import { dateRange, hours, today } from 'native-dates';

today().text;
dateRange('2026-09-01', '2026-09-07').format('medium');
hours(2).format('long');
```

## الإعداد الافتراضي على مستوى تطبيقات العميل

استدعِ [`configure()`](/api/configure/) مرة واحدة عند بدء التشغيل عندما يتضمّن تطبيقك منتقي لغة خاصًا به أو يستهدف إعدادًا محليًا ثابتًا، وحدّثه كلما بدّل القارئ اللغة.

تُنسَّق عندئذٍ كل قيمة ونطاق ومدة زمنية وتاريخ جزئي ودالة أسماء بذلك الإعداد المحلي:

```js title="main.js"
import { configure, date, days, monthNames, yearMonth } from 'native-dates';

configure({ locale: 'es-ES' });

date('2026-05-15').format('long'); // '15 de mayo de 2026'
yearMonth('2026-05').format('long'); // 'mayo de 2026'
days(2).text; // '2 días'
monthNames('short').slice(0, 3); // ['ene', 'feb', 'mar']

configure({ locale: null });
```

مرّر `locale: null` لاستعادة الإعداد المحلي الافتراضي لبيئة التشغيل.

## حمل الإعداد المحلي على القيمة

استدعِ [`locale()`](/api/date-time/#locale) على أي قيمة لإرجاع نسخة مضبوطة بذلك الإعداد المحلي، أو مرّر `{ locale }` إلى دالة مصنعية. وتعمل [`lang()`](/api/date-time/#lang) كاسم بديل عندما تفضّل الاسم الأقصر.

تحتفظ كل قيمة مشتقة منها بالإعداد المحلي نفسه: العمليات الحسابية وتحويلات المناطق الزمنية ومستخرجات التاريخ والوقت والنطاقات والمدد المقيسة كلها ترثه تلقائيًا:

```js
import { date, datetime } from 'native-dates';

const arrival = datetime('2026-05-15T14:30:00Z', 'Europe/Paris').locale('fr-FR');

arrival.text; // '15 mai 2026, 16:30 UTC+2'
arrival.plus(3, 'days').date.format('long'); // '18 mai 2026'

const stay = date('2026-09-01', { locale: 'de-DE' }).to('2026-09-07');
stay.format('medium'); // '01.–07.09.2026'
```

وعلى الخادم متعدّد المستخدمين، أرفق الإعداد المحلي لكل طلب عند قراءة القيمة بدل تعديل الإعدادات العامة للعملية بأكملها:

```js title="orders.js"
import { datetime } from 'native-dates';

function formatOrder(order, user) {
  const placed = datetime(order.placedAt, user.zone).locale(user.locale);
  return {
    placed: placed.format('long'),
    shipBy: placed.plus(2, 'days').date.format('medium'),
  };
}

formatOrder({ placedAt: '2026-05-15T14:30:00Z' }, { zone: 'Asia/Tokyo', locale: 'ja-JP' });
```

:::warning[تجنّب استدعاء configure لكل طلب على الخوادم]
تحدّث الإعدادات العامة حالةً مشتركة عبر عملية JavaScript بأكملها. وعلى الخادم متعدّد المستخدمين، قد يكتب طلب آخر فوق استدعاء `configure()` عبر حدود العمليات غير المتزامنة. أرفق `locale()` بالقيمة بدلًا من ذلك.
:::

يقرأ استدعاء `locale()` بلا معاملات الوسم النشط، أو يُرجع `undefined` إذا لم يُضبط أي وسم. ويمسح تمرير قيمة فارغة الوسم بحيث تتسلسل `locale(user.locale)` بأمان حتى عندما يكون حقل قاعدة البيانات فارغًا.

تعمل نصوص الإعداد المحلي الخام وترويسات HTTP `Accept-Language` مباشرةً دون معالجة مسبقة. فتُطبَّع الوسوم ذات الشرطة السفلية مثل `'en_US'` تلقائيًا، وتُرتَّب وسوم الترويسة حسب معامل الجودة مع استبعاد المدخلات ذات الوزن الصفري. وترمي نصوص الإعداد المحلي غير الصالحة خطأ [`unknownLocale`](/api/errors/#units-zones-and-formats):

```js
datetime('2026-05-15T14:30:00Z').locale('en_US').locale(); // 'en-US'
datetime('2026-05-15T14:30:00Z').locale('fr-CH;q=0.8, de;q=0.9, es;q=0').locale(); // ['de', 'fr-CH']
```

يتحكّم الإعداد المحلي للكائن في النص الموطّن وحدود الأسابيع وأيام عطلة نهاية الأسبوع، بينما تتجاهله المقارنات الدقيقة والفرز و[`equals()`](/api/date-time/#equals) والتحويل إلى نص ISO عبر [`toString()`](/api/date-time/#tostring):

```js
import { date } from 'native-dates';

const french = date('2026-05-15').locale('fr');
const japanese = date('2026-05-15').locale('ja');

french.equals(japanese); // true
french.toString(); // '2026-05-15'
french.to(japanese).locale(); // 'fr'
```

وعندما تجمع طريقةٌ بين قيمتين بإعدادين محليين مختلفين، تحتفظ القيمة التي استُدعيت عليها الطريقة بإعدادها المحلي.

## تجاوز التقويم أو اللهجة لاستدعاء واحد

مرّر وسم BCP 47 إلى `format()` عندما تحتاج تسمية واحدة إلى تقويم آخر أو نظام أرقام آخر أو لهجة إقليمية مختلفة، بينما تحتفظ القيمة نفسها بإعدادها المحلي القائم:

```js
import { date } from 'native-dates';

const reiwa = date('2019-05-01').locale('ja-JP');
reiwa.format('long'); // '2019年5月1日'
reiwa.format('long', 'ja-u-ca-japanese'); // '令和元年5月1日'

const eid = date('2026-03-20').locale('ar-SA');
eid.format('long', 'ar-SA-u-ca-islamic-umalqura'); // '١ شوال ١٤٤٧ هـ'
```

## كيف يُحدَّد الإعداد المحلي

عند تنسيق أي قيمة أو نطاق أو مدة زمنية أو عبارة وقت نسبي، تفحص Native Dates المصادر التالية بالترتيب وتستخدم أول إعداد محلي تجده:

| الأولوية | المصدر | متى يُستخدم |
|---|---|---|
| 1 | `value.format(spec, locale)` | عندما يحتاج استدعاء واحد إلى تقويم أو نظام كتابة أو لهجة إقليمية مختلفة. |
| 2 | `value.locale(tag)` أو `{ locale }` | في طلبات الخادم، أو سلاسل الاستدعاءات القابلة لإعادة الاستخدام، أو أقسام الواجهة الموطّنة. |
| 3 | `configure({ locale })` | عندما يتضمّن تطبيق العميل إعداد لغة عامًا أو مبدّل لغة. |
| 4 | الإعداد الافتراضي لـ `Intl` في بيئة التشغيل | عندما تتبع تطبيقات المتصفح لغة نظام القارئ. |

## الأسابيع وعطلات نهاية الأسبوع

تتبع حدود الأسابيع وترويسات أيام الأسبوع الإعداد المحلي النشط تلقائيًا؛ فتعتمد بيئة التشغيل يوم الأحد في الولايات المتحدة واليابان وكوريا والبرازيل، والسبت في مصر، والاثنين في معظم أوروبا والصين.

ولأن [`startOf('week')`](/api/calendar-date/#startof) و[`range('week')`](/api/calendar-date/#range) و[`weekdayNames()`](/api/month-names/#weekdaynames) تشترك في قاعدة اليوم الأول نفسها، تصطفّ ترويسات التقويم دائمًا مع شبكات الأسابيع:

```js
import { date, weekdayNames } from 'native-dates';

const wed = date('2026-11-18');

wed.locale('en-US').startOf('week').toString(); // '2026-11-15'
wed.locale('de-DE').startOf('week').toString(); // '2026-11-16'
wed.locale('ar-EG').startOf('week').toString(); // '2026-11-14'

weekdayNames('short', undefined, 'en-US')[0]; // 'Sun'
weekdayNames('short', undefined, 'de-DE')[0]; // 'Mo'
```

مرّر اسم يوم أسبوع بالإنجليزية صراحةً لتجاوز استدعاء واحد، أو اضبط `weekStart` (باسم يوم الأسبوع بالإنجليزية) في [`configure()`](/api/configure/) لتثبيت يوم بداية الأسبوع عبر كل الإعدادات المحلية. يعيد تمرير قيمة فارغة اتباع الإعداد المحلي، وترجع بيئات التشغيل التي تفتقر إلى بيانات الأسابيع افتراضيًا إلى الاثنين.

:::details[حماية التقارير ذات الأسابيع الثابتة]
يحتفظ الكائن بالإعداد المحلي للقيمة التي اشتُقّ منها. ثبّت `weekStart` أو افحص `day.weekStart` (من 1 ليوم الاثنين إلى 7 ليوم الأحد) كلما كانت الأسابيع مفتاحًا لبيانات مخزّنة مثل التقارير أو فترات الفوترة:

```js title="reports.js"
function weekKey(day) {
  if (day.weekStart !== 1) {
    throw new Error('weekly reports are keyed by Monday weeks');
  }
  return day.startOf('week').toString();
}
```

تبدأ أرقام أسابيع ISO من `weekOfYear` دائمًا من يوم الاثنين، وتتبع `dayOfWeek` الترقيم نفسه بدءًا من الاثنين.
:::

وتتبع فحوصات عطلة نهاية الأسبوع الإعداد المحلي النشط أيضًا؛ فتعدّ [`isWeekend()`](/api/calendar-date/#calendar-predicates) و[`isWeekday()`](/api/calendar-date/#calendar-predicates) الجمعة والسبت عطلة نهاية الأسبوع في السعودية ومصر، والجمعة وحدها في إيران، والأحد وحده في الهند، بينما تعتمد معظم الإعدادات المحلية الأخرى السبت والأحد:

```js
const friday = date('2026-11-20');

friday.locale('en-US').isWeekend(); // false
friday.locale('ar-SA').isWeekend(); // true
```

## تخصيص أسماء أيام الأسبوع والأعداد الترتيبية

تأتي أسماء الأشهر وأيام الأسبوع من بيئة التشغيل، مطابقةً لما يطبعه جهاز القارئ. ويفتقر رمزا تنسيق إلى حقل قياسي في المنصة: أيام الأسبوع بحرفين عبر `dd`، والأعداد الترتيبية للأيام عبر `Do`.

تقتطع `dd` افتراضيًا الاسم المختصر ليوم الأسبوع إلى حرفين في أنظمة الكتابة التي تختصر بهذه الطريقة، وتستخدم الاسم المضغوط لبيئة التشغيل فيما عدا ذلك. وتنسّق `Do` لواحق الأعداد الترتيبية في الإنجليزية، وعلامة اليوم الخاصة بالإعداد المحلي في غيرها مثل `'6.'` بالألمانية.

تجاوز أيًا منهما عالميًا عبر `weekdayNames` و`ordinals` في [`configure()`](/api/configure/). ترث الوسوم الإقليمية مثل `'fr-CA'` مدخلات لغتها الأساسية وتطبّق تجاوزاتها فوقها، بينما تبقى القوالب الجاهزة وخيارات `Intl` دون تغيير. راجع [التخصيص](/guides/customization/#custom-weekday-names-and-ordinals) للاطلاع على أمثلة.

تصفّح [أمثلة اللغات](/examples/#localization) وأدلة كل لغة ضمن قسم **الوقت حسب اللغة** في الشريط الجانبي للتعرّف على الحالات الخاصة بالأقاليم وأنظمة الكتابة والتقويمات. اقرأ تاليًا [أنواع الوقت](/guides/types-of-time/) لاختيار النوع المناسب لكل قيمة في تطبيقك.

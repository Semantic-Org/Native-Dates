تتضمّن محركات JavaScript الحديثة واجهة `Temporal` للعمليات الحسابية على التقويم والمناطق الزمنية، إلى جانب واجهة `Intl` للتنسيق الموطّن. تغلّف Native Dates هاتين الواجهتين المدمجتين بصياغة مقروءة قريبة من اللغة الطبيعية وبلا أي اعتماديات في بيئة التشغيل.

```js
import { date, now, today } from 'native-dates';

const due = today().plus(2, 'weeks');
const standup = date('2026-11-16')
  .at('9:30am', 'America/Los_Angeles')
  .in('Europe/Berlin');
```

بما أن بيئة التشغيل تحوي بالفعل قاعدة بيانات IANA للمناطق الزمنية وقواعد الإعدادات المحلية، تعمل كل منطقة ولغة من دون شحن جداول إضافية للمناطق أو الإعدادات المحلية في حزمتك.

## أنواع منفصلة لمهام منفصلة

يستخدم كائن `Date` المدمج في JavaScript نوعًا واحدًا لكل شيء، سواء قصدت عطلة رسمية أو ساعة افتتاح متجر أو طابعًا زمنيًا في قاعدة بيانات. تمنح Native Dates كل مفهوم نوعًا مستقلًا بحيث لا تحمل القيمة إلا الحقول التي تناسبها:

- [`CalendarDate`](/api/calendar-date/) ليوم تقويمي مثل 10 مايو 2026، لا يتأثر بالمناطق الزمنية
- [`Time`](/api/time/) لوقت اليوم مثل 9:30 صباحًا، يلتفّ بسلاسة عند منتصف الليل
- [`DateTime`](/api/date-time/) للحظة زمنية محدّدة مرتبطة بمنطقة زمنية
- [`Duration`](/api/duration/) لمدة زمنية مثل 90 دقيقة أو أسبوعين
- [`YearMonth`](/api/year-month/) و[`MonthDay`](/api/month-day/) لأشهر الفوترة وتواريخ انتهاء البطاقات وأعياد الميلاد المتكرّرة
- [النطاقات](/api/ranges/) للامتدادات المحصورة بين تاريخين أو وقتين أو لحظتين زمنيتين

يعمل قياس الفواصل وبناء النطاقات والتنسيق بالقوالب الجاهزة الموطّنة أو بأنماط الرموز مباشرةً دون إعداد إضافي:

```js
import { dateRange, datetime, monthDay, now, timeRange, yearMonth } from 'native-dates';

const deadline = datetime('2027-01-01T00:00:00Z');
now().until(deadline).format('long');

const sprint = dateRange('2026-11-02', '2026-11-15');
const shift = timeRange('9:00am', '5:00pm');
sprint.contains('2026-11-10'); // true
shift.duration.hours; // 8

const billing = yearMonth('2026-11');
const birthday = monthDay('10/17');
```

اقرأ دليل [أنواع الوقت](/guides/types-of-time/) تاليًا لتعرف كيف تختار النوع الأنسب وتنتقل من نوع إلى آخر.

## قيم غير قابلة للتعديل

كل كائن في المكتبة غير قابل للتعديل. تُرجع الطرق مثل [`plus()`](/api/date-time/#plus) أو [`in()`](/api/date-time/#in) قيمة جديدة دائمًا وتترك الأصل دون مساس.

بذلك لا يمكن لتمرير تاريخ إلى دالة مساعدة أو مكوّن واجهة أن يُعدّل حالة المستدعي خفيةً:

```js
const original = date('2026-11-16').at('9:30am', 'America/Los_Angeles');
const moved = original.plus(1, 'hour');

original.text; // 'Nov 16, 2026, 9:30 AM PST'
moved.text; // 'Nov 16, 2026, 10:30 AM PST'
```

توفّر كل قيمة أيضًا خاصية `.text` التي تعرض ملخّصًا مقروءًا بالإعداد المحلي النشط، إلى جانب مخرجات `util.inspect` مخصّصة بحيث تطبع `console.log()` في Node معاينة موجزة في سطر واحد:

```js
import { time } from 'native-dates';

date('2026-05-10').text; // 'May 10, 2026'
time('9:30am').text; // '9:30 AM'
```

:::tip[مقارنة القيم]
لأن الطرق تُرجع كائنات جديدة، يفحص المعامل `===` مراجع الكائنات لا تساوي القيم. استدعِ [`equals()`](/api/date-time/#equals) للتحقق مما إذا كان كائنان يمثّلان التاريخ أو الوقت أو اللحظة الزمنية نفسها.
:::

## النواة والإضافات

تغطّي حزمة [`native-dates`](/guides/installation/) الأساسية إنشاء القيم والمناطق الزمنية والحسابات التقويمية والتواريخ الجزئية والنطاقات والمدد الزمنية وعبارات الوقت النسبي والقوالب الجاهزة الموطّنة وأنماط الرموز.

أمّا الإضافات الاختيارية للبحث بأسماء المدن والاختصارات، والتحليل بالوضع المرن، وطرق `Date` التقليدية، فتتوفّر في [`@native-dates/plugins`](/plugins/) كمسارات فرعية مستقلة. راجع [التخصيص](/guides/customization/#adding-plugins) لتثبيت الإضافات أو ضبط الإعدادات الافتراضية على مستوى التطبيق.

انتقل إلى [التثبيت](/guides/installation/) لإضافة الحزمة إلى مشروعك وإعداد حزمة التوافق (polyfill) إذا كنت تدعم Safari.

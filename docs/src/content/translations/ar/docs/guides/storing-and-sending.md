يتحوّل كل نوع إلى نص ISO 8601 قياسي عند تحويله إلى نص أو تمريره إلى `JSON.stringify()`. وتُقرأ تلك النصوص مباشرةً عبر الدالة المصنعية المطابقة على الطرف الآخر.

## تنسيق JSON ونصوص النقل

مرّر القيم مباشرةً إلى `JSON.stringify()` من دون دوال استبدال مخصّصة أو كائنات تغليف:

```js
import { date, duration, time } from 'native-dates';

const standup = date('2026-11-16').at('9:30am', 'America/Los_Angeles');

JSON.stringify({
  startsAt: standup,
  dueOn: date('2026-11-16'),
  opensAt: time('9:30am'),
  length: duration('1h 30m'),
});
// '{"startsAt":"2026-11-16T17:30:00.000Z","dueOn":"2026-11-16","opensAt":"09:30:00","length":"PT1H30M"}'
```

| النوع | ناتج النقل | حقل حمولة شائع |
|---|---|---|
| [`DateTime`](/api/date-time/) | `'2026-11-16T17:30:00.000Z'` | طوابع التدقيق ومواعيد إقلاع الرحلات ولحظات الاجتماعات |
| [`CalendarDate`](/api/calendar-date/) | `'2026-11-16'` | تواريخ الاستحقاق والعطلات وليالي الحجوزات |
| [`Time`](/api/time/) | `'09:30:00'` | ساعات عمل المتاجر وأوقات التذكير اليومية |
| [`Duration`](/api/duration/) | `'PT1H30M'` | مهل الانتظار واتفاقيات مستوى الخدمة ومدد الفوترة والمؤقتات |
| [`YearMonth`](/api/year-month/) | `'2026-11'` | أشهر الفوترة وتواريخ انتهاء البطاقات وحقول إدخال الأشهر |
| [`MonthDay`](/api/month-day/) | `'10-17'` | أعياد الميلاد المتكرّرة والعطلات السنوية بلا سنة ميلاد |
| [النطاقات](/api/ranges/) | `'2026-11-01/2026-11-07'` | نوافذ الحجز ودورات العمل وفترات ISO 8601 المفصولة بشرطة مائلة |

عندما تتوقع واجهة API خارجية أو مفتاح ذاكرة مؤقتة أو عمود أعداد صحيحة رقمًا، اقرأ العدّ منذ 1970 بالوحدة المطلوبة. تسمّي كل خاصية وحدتها صراحةً لأن بعض الأنظمة تعدّ بالثواني وبعضها الآخر بالمللي ثانية:

```js
standup.toString(); // '2026-11-16T17:30:00.000Z'
standup.epochSeconds; // 1794850200
standup.epochMilliseconds; // 1794850200000
duration('1h 30m').toMilliseconds(); // 5400000
```

## إعادة القراءة إلى الشيفرة

مرّر كل نص نقل إلى الدالة المصنعية المطابقة له عند قراءة استجابات JSON أو صفوف قواعد البيانات أو معاملات روابط URL:

```js
import { date, dateRange, datetime, duration, time, yearMonth } from 'native-dates';

const startsAt = datetime('2026-11-16T17:30:00.000Z', 'America/Los_Angeles');
const dueOn = date('2026-11-16');
const opensAt = time('09:30:00');
const length = duration('PT1H30M');
const billing = yearMonth('2026-11');
const window = dateRange('2026-11-01/2026-11-07');
```

يُكتَب كل `DateTime` بتوقيت UTC بحيث ينتج عميلان يسجّلان الحدث نفسه نصين متطابقين. وعند إعادة قراءة النص مع تمرير منطقة زمنية، تُعرض لحظة UTC الدقيقة بالتوقيت المحلي دون تغيير توقيت وقوعها.

## الأحداث المستقبلية والمتكرّرة

للأحداث الماضية مثل إيصالات الطلبات أو سجلات الخادم، يكفي طابع UTC الزمني وحده. أمّا الأحداث المستقبلية التي يجدولها البشر فتحتاج إلى تخزين اسم منطقة IANA (`zone`) إلى جانب الطابع الزمني.

```js
import { date, datetime } from 'native-dates';

const standup = date('2026-11-16').at('9:30am', 'America/Los_Angeles');
const row = {
  startsAt: standup.toString(),
  zone: standup.zone, // 'America/Los_Angeles'
};

const nextWeek = datetime(row.startsAt, row.zone).plus(1, 'week');
nextWeek.hour; // 9
```

مع حفظ المنطقة الزمنية، تحافظ إضافة الأسابيع أو الأشهر على موعد الساعة 9:30 صباحًا المحلي عبر انتقالات التوقيت الصيفي، كما تلتقط تلقائيًا أي تعديلات تشريعية مستقبلية على قواعد التوقيت المحلي.

:::tip[خزّن أسماء IANA لا الإزاحات]
تصف الإزاحة مثل `'-08:00'` الشتاء فقط في لوس أنجلوس. خزّن `zone` متى احتاجت الحسابات التقويمية المستقبلية إلى اتباع تحوّلات التوقيت الصيفي المحلية.
:::

## أعمدة قواعد البيانات

طابق نوع عمود SQL مع نوع القيمة التي تتعامل معها بحيث تفرض قاعدة البيانات الحدود نفسها التي تفرضها شيفرة تطبيقك.

| النوع | عمود SQL | سبب ملاءمته |
|---|---|---|
| `DateTime` | `timestamptz` أو `bigint` | يخزّن لحظة UTC دقيقة بلا لبس |
| `CalendarDate` | `date` | يخزّن `YYYY-MM-DD` دون انزياحات منتصف الليل بين المناطق الزمنية |
| `Time` | `time` | يخزّن `HH:MM:SS` دون اختلاق تاريخ وهمي |
| `Duration` | `interval` أو `text` | يخزّن مددًا مهيكلة أو نصوص ISO 8601 المبدوءة بـ `PT` |

تجنّب أعمدة SQL من نوع `timestamp` المجرّدة بلا منطقة زمنية للحظات الزمنية الفعلية؛ لأن مشغّلات قواعد البيانات كثيرًا ما تعيد تفسير الطوابع المجرّدة وفق المنطقة الزمنية المحلية للخادم.

## حقول إدخال HTML وروابط URL

تقرأ عناصر إدخال HTML الأصلية للتاريخ والشهر والوقت نصوص ISO نفسها التي تنتجها الأنواع الأساسية وتكتبها، وتحمل معاملات البحث في روابط URL التنسيق الموجز نفسه.

```js
import { date, time, yearMonth } from 'native-dates';

// <input type="date" value="2026-11-16">
const due = date('2026-11-16');
due.toString(); // '2026-11-16'

// <input type="month" value="2026-11">
const billing = yearMonth('2026-11');
billing.toString(); // '2026-11'

// <input type="time" value="09:30">
const opens = time('09:30');
opens.toString().slice(0, 5); // '09:30'

const params = new URLSearchParams({ from: due.toString() });
params.toString(); // 'from=2026-11-16'
```

كما تتفادى قراءة حقول التاريخ عبر [`date()`](/api/date-fn/) الخطأ الشهير في `new Date('2026-11-16')` حيث ينزاح منتصف ليل UTC يومًا إلى الوراء في مناطق نصف الكرة الغربي.

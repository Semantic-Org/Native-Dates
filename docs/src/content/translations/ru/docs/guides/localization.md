---

Native Dates форматирует значения с помощью встроенных данных `Intl` движка JavaScript. Все языки, системы письма, правила множественных форм и календарные системы работают без загрузки файлов локалей.

Способ настройки локали зависит от вашей среды выполнения. Выберите область действия, которая соответствует архитектуре приложения:

- **Локаль среды выполнения по умолчанию** — когда браузерное приложение подстраивается под системные настройки пользователя
- **Глобальная [`configure()`](/api/configure/)** — когда в клиентском приложении есть собственный переключатель языка или фиксированная локаль
- **На уровне значения через [`locale()`](/api/date-time/#locale)** — когда сервер форматирует данные отдельно для каждого запроса или цепочка вызовов несёт собственную локаль
- **Точечное переопределение в [`format()`](/api/date-time/#format)** — когда для одной конкретной надписи нужен другой календарь или региональный вариант

## Без настройки в браузере

Если локаль нигде не задана, каждое свойство `.text`, вызов `format()`, диапазон, длительность и функции названий месяцев и дней недели используют активную локаль среды выполнения.

Однопользовательским браузерным приложениям, которые следуют системным настройкам пользователя, дополнительная настройка не нужна:

```js
import { dateRange, hours, today } from 'native-dates';

today().text;
dateRange('2026-09-01', '2026-09-07').format('medium');
hours(2).format('long');
```

## Глобальная локаль в клиентских приложениях

Вызовите [`configure()`](/api/configure/) один раз при запуске, если в приложении есть свой выбор языка или фиксированная целевая локаль. При смене языка пользователем просто вызовите `configure()` снова.

Все значения, диапазоны, длительности, частичные даты и функции названий месяцев и дней недели начнут форматироваться в заданной локали:

```js title="main.js"
import { configure, date, days, monthNames, yearMonth } from 'native-dates';

configure({ locale: 'es-ES' });

date('2026-05-15').format('long'); // '15 de mayo de 2026'
yearMonth('2026-05').format('long'); // 'mayo de 2026'
days(2).text; // '2 días'
monthNames('short').slice(0, 3); // ['ene', 'feb', 'mar']

configure({ locale: null });
```

Передайте `locale: null`, чтобы вернуться к локали среды выполнения по умолчанию.

## Привязка локали к значению

Вызовите [`locale()`](/api/date-time/#locale) на любом значении, чтобы получить копию с этой локалью, или передайте `{ locale }` в фабричную функцию. Если хочется более короткого имени, используйте псевдоним [`lang()`](/api/date-time/#lang).

Все производные значения наследуют ту же локаль: арифметика, смена часового пояса, извлечение даты или времени суток, диапазоны и измеренные длительности сохраняют её автоматически:

```js
import { date, datetime } from 'native-dates';

const arrival = datetime('2026-05-15T14:30:00Z', 'Europe/Paris').locale('fr-FR');

arrival.text; // '15 mai 2026, 16:30 UTC+2'
arrival.plus(3, 'days').date.format('long'); // '18 mai 2026'

const stay = date('2026-09-01', { locale: 'de-DE' }).to('2026-09-07');
stay.format('medium'); // '01.–07.09.2026'
```

На многопользовательском сервере привязывайте локаль конкретного запроса при чтении значения, а не изменяйте глобальную конфигурацию процесса:

```js title="orders.js"
import { datetime } from 'native-dates';

function formatOrder(order, user) {
  const placed = datetime(order.placedAt, user.zone).locale(user.locale);
  return {
    placed: placed.format('long'),
    shipBy: placed.plus(2, 'days').date.format('medium'),
  };
}

formatOrder({ placedAt: '2026-05-15T14:30:00Z' }, { zone: 'Asia/Tokyo', locale: 'ja-JP' });
```

:::warning[Не вызывайте configure на каждый запрос сервера]
Глобальная конфигурация меняет общее состояние для всего процесса JavaScript. На многопользовательском сервере другой запрос может перезаписать настройки `configure()` во время асинхронного ожидания. Вместо этого привязывайте `locale()` к самому значению.
:::

Вызов `locale()` без аргументов возвращает активный тег локали или `undefined`, если локаль не задана. Пустое значение сбрасывает привязку, поэтому цепочка `locale(user.locale)` безопасно работает даже для пустого столбца из базы данных.

Сырые строки локалей и HTTP-заголовки `Accept-Language` принимаются без предварительной обработки. Теги с подчёркиванием вроде `'en_US'` нормализуются автоматически, а теги из заголовка сортируются по весу `q` с отбрасыванием записей с нулевым весом. Некорректные строки локалей выбрасывают ошибку [`unknownLocale`](/api/errors/#units-zones-and-formats):

```js
datetime('2026-05-15T14:30:00Z').locale('en_US').locale(); // 'en-US'
datetime('2026-05-15T14:30:00Z').locale('fr-CH;q=0.8, de;q=0.9, es;q=0').locale(); // ['de', 'fr-CH']
```

Локаль экземпляра влияет на форматирование текста, границы недель и выходные дни. Точные сравнения, сортировка, [`equals()`](/api/date-time/#equals) и сериализация ISO через [`toString()`](/api/date-time/#tostring) её игнорируют:

```js
import { date } from 'native-dates';

const french = date('2026-05-15').locale('fr');
const japanese = date('2026-05-15').locale('ja');

french.equals(japanese); // true
french.toString(); // '2026-05-15'
french.to(japanese).locale(); // 'fr'
```

Если метод объединяет два значения с разными локалями, результат сохраняет локаль того значения, на котором был вызван метод.

## Точечное переопределение календаря и регионального варианта

Передайте тег BCP 47 в `format()`, когда для одной конкретной надписи нужен другой календарь, система цифр или региональный вариант. Само значение при этом сохраняет прежнюю локаль:

```js
import { date } from 'native-dates';

const reiwa = date('2019-05-01').locale('ja-JP');
reiwa.format('long'); // '2019年5月1日'
reiwa.format('long', 'ja-u-ca-japanese'); // '令和元年5月1日'

const eid = date('2026-03-20').locale('ar-SA');
eid.format('long', 'ar-SA-u-ca-islamic-umalqura'); // '١ شوال ١٤٤٧ هـ'
```

## Приоритет выбора локали

При форматировании любого значения, диапазона, длительности или относительной фразы Native Dates проверяет источники по порядку и берёт первую найденную локаль:

| Приоритет | Источник | Когда использовать |
|---|---|---|
| 1 | `value.format(spec, locale)` | Для одного вызова нужен другой календарь, письменность или региональный вариант. |
| 2 | `value.locale(tag)` или `{ locale }` | Серверные запросы, переиспользуемые цепочки или локализованные фрагменты интерфейса. |
| 3 | `configure({ locale })` | В клиентском приложении есть глобальная настройка или переключатель языка. |
| 4 | Локаль `Intl` среды выполнения | Браузерное приложение следует системным настройкам пользователя. |

## Недели и выходные

Границы недель и заголовки дней недели автоматически подстраиваются под активную локаль. Среда выполнения считает первым днём недели воскресенье в США, Японии, Корее и Бразилии, субботу в Египте и понедельник в большинстве стран Европы и в Китае.

Поскольку [`startOf('week')`](/api/calendar-date/#startof), [`range('week')`](/api/calendar-date/#range) и [`weekdayNames()`](/api/month-names/#weekdaynames) используют одно и то же правило первого дня недели, заголовки календаря всегда совпадают с сеткой недель:

```js
import { date, weekdayNames } from 'native-dates';

const wed = date('2026-11-18');

wed.locale('en-US').startOf('week').toString(); // '2026-11-15'
wed.locale('de-DE').startOf('week').toString(); // '2026-11-16'
wed.locale('ar-EG').startOf('week').toString(); // '2026-11-14'

weekdayNames('short', undefined, 'en-US')[0]; // 'Sun'
weekdayNames('short', undefined, 'de-DE')[0]; // 'Mo'
```

Чтобы переопределить начало недели для одного вызова, передайте английское название дня недели явно либо задайте `weekStart` (английским названием вроде `'monday'`) в [`configure()`](/api/configure/), чтобы зафиксировать его для всех локалей. Пустое значение возвращает выбор дня по локали, а среды выполнения без данных о неделях используют понедельник по умолчанию.

:::details[Защита отчётов с фиксированным началом недели]
Экземпляр наследует локаль значения, из которого был получен. Зафиксируйте `weekStart` или проверяйте `day.weekStart` (от 1 для понедельника до 7 для воскресенья) везде, где недели служат ключами хранимых данных вроде отчётов или расчётных периодов:

```js title="reports.js"
function weekKey(day) {
  if (day.weekStart !== 1) {
    throw new Error('weekly reports are keyed by Monday weeks');
  }
  return day.startOf('week').toString();
}
```

Номера недель ISO в `weekOfYear` всегда отсчитываются с понедельника, и `dayOfWeek` использует ту же нумерацию с понедельника.
:::

Проверка выходных тоже опирается на активную локаль. [`isWeekend()`](/api/calendar-date/#calendar-predicates) и [`isWeekday()`](/api/calendar-date/#calendar-predicates) считают выходными пятницу и субботу в Саудовской Аравии и Египте и только пятницу в Иране. В Индии выходным считается только воскресенье, а в большинстве остальных локалей — суббота и воскресенье:

```js
const friday = date('2026-11-20');

friday.locale('en-US').isWeekend(); // false
friday.locale('ar-SA').isWeekend(); // true
```

## Пользовательские названия дней недели и порядковые числа

Названия месяцев и дней недели берутся из среды выполнения, поэтому совпадают с тем, что отображает устройство пользователя. Только два токена форматирования не имеют стандартного поля на уровне платформы: двухбуквенные дни недели (`dd`) и порядковые номера дней (`Do`).

По умолчанию `dd` укорачивает краткое название дня недели до двух букв там, где это естественно для письменности, а в остальных случаях использует узкую форму из среды выполнения. `Do` выводит английские порядковые суффиксы в английском языке и локальный маркер дня в остальных локалях — например, `'6.'` в немецкой.

Оба варианта можно переопределить глобально через `weekdayNames` (с английскими ключами дней недели) и `ordinals` в [`configure()`](/api/configure/). Региональные теги вроде `'fr-CA'` наследуют настройки базового языка и накладывают поверх собственные переопределения, при этом пресеты и параметры `Intl` остаются нетронутыми. Примеры смотрите в руководстве [Настройка](/guides/customization/#custom-weekday-names-and-ordinals).

Региональные особенности, письменности и календарные системы разобраны в [языковых примерах](/examples/#localization) и отдельных руководствах в разделе **Языки и локали** бокового меню. Далее прочитайте руководство [Типы времени](/guides/types-of-time/), чтобы подобрать подходящий тип для каждого значения в вашем приложении.

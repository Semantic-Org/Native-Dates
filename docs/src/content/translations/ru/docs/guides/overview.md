Современные движки JavaScript уже содержат `Temporal` для календарной арифметики и работы с часовыми поясами, а также `Intl` для локализованного форматирования. Native Dates оборачивает эти встроенные API в читаемый, естественный синтаксис без единой внешней зависимости.

```js
import { date, now, today } from 'native-dates';

const due = today().plus(2, 'weeks');
const standup = date('2026-11-16')
  .at('9:30am', 'America/Los_Angeles')
  .in('Europe/Berlin');
```

Поскольку среда выполнения уже включает базу часовых поясов IANA и правила локалей, все регионы и языки работают сразу — без дополнительных таблиц поясов или файлов локалей в бандле.

## Отдельные типы для разных задач

Встроенный объект `Date` в JavaScript один на всё: и для праздника, и для времени открытия магазина, и для метки времени из базы данных. В Native Dates у каждой сущности свой тип, поэтому значения хранят только осмысленные поля:

- [`CalendarDate`](/api/calendar-date/) — календарная дата вроде 10 мая 2026 года, не зависящая от часовых поясов
- [`Time`](/api/time/) — время суток вроде 9:30, корректно переходящее через полночь
- [`DateTime`](/api/date-time/) — конкретный момент времени в заданном часовом поясе
- [`Duration`](/api/duration/) — длительность вроде 90 минут или 2 недель
- [`YearMonth`](/api/year-month/) и [`MonthDay`](/api/month-day/) — расчётные периоды, сроки действия карт и ежегодные дни рождения
- [Диапазоны](/api/ranges/) — промежутки между двумя датами, значениями времени суток или моментами времени

Измерение промежутков, создание диапазонов и форматирование с помощью локализованных пресетов или шаблонов токенов работают из коробки:

```js
import { dateRange, datetime, monthDay, now, timeRange, yearMonth } from 'native-dates';

const deadline = datetime('2027-01-01T00:00:00Z');
now().until(deadline).format('long');

const sprint = dateRange('2026-11-02', '2026-11-15');
const shift = timeRange('9:00am', '5:00pm');
sprint.contains('2026-11-10'); // true
shift.duration.hours; // 8

const billing = yearMonth('2026-11');
const birthday = monthDay('10/17');
```

Далее прочитайте руководство [Типы времени](/guides/types-of-time/), чтобы понять, какой тип выбрать и как переходить от одного к другому.

## Неизменяемые значения

Каждый экземпляр неизменяем. Вызов методов вроде [`plus()`](/api/date-time/#plus) или [`in()`](/api/date-time/#in) всегда возвращает новое значение, оставляя исходное нетронутым.

Передача даты во вспомогательную функцию или UI-компонент не может случайно изменить состояние вызывающего кода:

```js
const original = date('2026-11-16').at('9:30am', 'America/Los_Angeles');
const moved = original.plus(1, 'hour');

original.text; // 'Nov 16, 2026, 9:30 AM PST'
moved.text; // 'Nov 16, 2026, 10:30 AM PST'
```

У каждого значения также есть геттер `.text` с читаемой строкой в активной локали и собственный вывод `util.inspect`, поэтому `console.log()` в Node печатает короткий однострочный предпросмотр:

```js
import { time } from 'native-dates';

date('2026-05-10').text; // 'May 10, 2026'
time('9:30am').text; // '9:30 AM'
```

:::tip[Сравнение значений]
Поскольку методы возвращают новые экземпляры, оператор `===` сравнивает ссылки на объекты, а не значения. Вызовите [`equals()`](/api/date-time/#equals), чтобы проверить, представляют ли два экземпляра одну и ту же дату, время суток или момент времени.
:::

## Ядро и плагины

Основной пакет [`native-dates`](/guides/installation/) включает всё необходимое: создание значений, часовые пояса, календарную арифметику, частичные даты, диапазоны, длительности, относительные фразы, локализованные пресеты и шаблоны токенов.

Дополнительные плагины для поиска часовых поясов по городам и аббревиатурам, нестрогого разбора и методов устаревшего `Date` вынесены в [`@native-dates/plugins`](/plugins/) отдельными точками входа. О подключении плагинов и глобальных настройках читайте в руководстве [Настройка](/guides/customization/#adding-plugins).

Перейдите к руководству [Установка](/guides/installation/), чтобы добавить пакет в проект и при необходимости подключить полифил для Safari.

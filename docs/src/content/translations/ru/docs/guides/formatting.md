Native Dates использует встроенные форматтеры `Intl` платформы и автоматически кэширует их. Вы получаете локализованный вывод для любых языков и регионов без добавления файлов локалей в бандл.

## Быстрый вывод через text и пресеты

У каждого экземпляра есть свойство `.text`, отформатированное в активной локали. Вызов [`format()`](/api/date-time/#format) без аргументов использует пресет по умолчанию для конкретного типа:

```js
import { date, datetime, duration, time } from 'native-dates';

const standup = datetime('2026-11-16T09:30', 'America/Los_Angeles');
standup.text; // 'Nov 16, 2026, 9:30 AM PST'
standup.format(); // 'Nov 16, 2026, 9:30 AM'

date('2026-11-16').text; // 'Nov 16, 2026'
time('9:30am').text; // '9:30 AM'
duration('1h 30m').text; // '1 hour, 30 minutes'
```

Передайте в `format()` имя пресета, чтобы выбрать степень подробности:

| Пресет | Пример | Поддерживаемые типы и вывод |
|---|---|---|
| `'short'` | `'5/4/26, 9:30 AM'` | Числовая дата или краткое время суток для дат, времени суток, моментов времени, частичных дат и длительностей. |
| `'medium'` | `'May 4, 2026, 9:30 AM'` | Сокращённое название месяца для дат и моментов времени или время с секундами для [`Time`](/api/time/). |
| `'long'` | `'May 4, 2026 at 9:30 AM'` | Полное название месяца, время с секундами для `Time` или полные названия единиц для [`Duration`](/api/duration/). |
| `'full'` | `'Monday, May 4, 2026 at 9:30 AM'` | Полные названия дня недели и месяца для дат и моментов времени или полное название месяца для частичных дат. |
| `'date'` | `'May 4, 2026'` | Календарная дата для [`DateTime`](/api/date-time/) и [`CalendarDate`](/api/calendar-date/). |
| `'time'` | `'9:30 AM'` | Краткое время суток для `DateTime` и `Time`. |
| `'month'` | `'May 2026'` | Полное название месяца и год для `DateTime`, `CalendarDate` и [`YearMonth`](/api/year-month/). |
| `'text'` | `'May 4, 2026, 9:30 AM PDT'` | Дата, время суток и краткое имя часового пояса для `DateTime` либо собственные поля для остальных типов. |

:::details[Названия пресетов из Moment и Day.js]
Ядро также принимает локализованные названия пресетов из Moment и Day.js:

| Пресет | Пример | Локализованные поля |
|---|---|---|
| `'LT'`, `'LTS'` | `'9:30 AM'`, `'9:30:00 AM'` | Краткое время суток или время с секундами. |
| `'L'`, `'l'` | `'05/04/2026'`, `'5/4/2026'` | Числовые год, месяц и день — с ведущими нулями или без них. |
| `'LL'`, `'ll'` | `'May 4, 2026'` | Полное или сокращённое название месяца с днём и годом. |
| `'LLL'`, `'lll'` | `'May 4, 2026 at 9:30 AM'` | Полная или сокращённая дата вместе с кратким временем суток. |
| `'LLLL'`, `'llll'` | `'Monday, May 4, 2026 at 9:30 AM'` | Полный или сокращённый день недели, дата и краткое время суток. |
:::

Даты, время суток, [годы и месяцы](/api/year-month/) и [месяцы и дни](/api/month-day/) принимают любой из перечисленных пресетов и выводят только те поля, которыми располагают. [Длительности](/api/duration/) дополнительно поддерживают компактный и цифровой стили:

```js
import { date, duration, time, yearMonth } from 'native-dates';

date('2026-11-16').format('full', 'en-US'); // 'Monday, November 16, 2026'
yearMonth('2026-11').format('LL', 'en-US'); // 'November 2026'
time('9:30:15am').format('LTS', 'en-US'); // '9:30:15 AM'

const span = duration({ hours: 2, minutes: 15 });
span.format('narrow', 'en-US'); // '2h 15m'
span.format('digital', 'en-US'); // '2:15:00'
```

## Локали и параметры Intl

Задайте локаль по умолчанию один раз через [`configure()`](/api/configure/), привяжите локаль к конкретному значению через [`locale()`](/api/date-time/#locale) или передайте тег в один вызов `format()`. Рекомендации для клиентских приложений и многопользовательских серверов собраны в руководстве [Локализация](/guides/localization/):

```js
import { configure, datetime } from 'native-dates';

const standup = datetime('2026-11-16T09:30', 'Europe/Berlin');
standup.locale('de-DE').plus(1, 'week').format('long'); // '23. November 2026 um 09:30'
standup.format('long', 'ja-JP'); // '2026年11月16日 9:30'

configure({ locale: 'en-GB' });
configure({ locale: null });
```

Если ни один пресет не подходит под нужную разметку, передайте объект параметров напрямую в базовый форматтер:

```js
import { date } from 'native-dates';

const day = date('2026-11-16');

day.format({ weekday: 'long' }, 'en-US'); // 'Monday'
day.format({ month: 'short', day: 'numeric' }, 'en-US'); // 'Nov 16'
```

Поскольку каждый тип содержит только свои поля, пресеты сами подстраиваются под грамматику, множественные формы, письменность и календарные системы без файлов локалей. Краевые случаи для разных языков разобраны в [языковых примерах](/examples/):

```js
import { date, days, yearMonth } from 'native-dates';

date('2019-05-01').format('long', 'ja-u-ca-japanese'); // '令和元年5月1日'
yearMonth('2026-05').format('long', 'ru'); // 'май 2026 г.'
date('2026-05-01').format('long', 'ru'); // '1 мая 2026 г.'
days(2).format('long', 'ar'); // 'يومان'
```

:::tip[Вывод для пользователей и передача данных]
Используйте `format()` только для текста, который видят люди. Для сохранения в базу или передачи по сети вызывайте [`toString()`](/api/date-time/#tostring) или сериализуйте значения в JSON, чтобы данные оставались в стабильном формате ISO 8601. Подробнее — в руководстве [Хранение и передача](/guides/storing-and-sending/).
:::

## Шаблоны токенов

Когда нужен жёстко заданный формат, передайте в `format()` шаблон токенов. Литеральный текст заключите в квадратные скобки, чтобы он копировался в вывод без изменений:

```js
import { datetime, monthDay, yearMonth } from 'native-dates';

const standup = datetime('2026-11-16T09:30', 'America/Los_Angeles');

standup.format('YYYY-MM-DD HH:mm'); // '2026-11-16 09:30'
standup.format('YYYY-MM-DDTHH:mmZ'); // '2026-11-16T09:30-08:00'
standup.format('dddd, MMM D [at] h:mm A', 'en-US'); // 'Monday, Nov 16 at 9:30 AM'
yearMonth('2026-11').format('MMM YYYY', 'en-US'); // 'Nov 2026'
monthDay('11-16').format('MMMM Do', 'en-US'); // 'November 16th'
```

Названия месяцев и дней недели внутри шаблона токенов берутся из `Intl` для активной локали. Цифры и годы остаются в западной записи ISO, чтобы шаблоны вроде `'YYYY-MM-DD'` оставались машиночитаемыми везде. Регистр токенов повторяет Moment и Day.js: `YYYY` и `DD` пишутся в верхнем регистре, в отличие от строчных `yyyy` и `dd` в LDML и date-fns (здесь `dd` обозначает двухбуквенный день недели).

:::details[Все токены форматирования]
| Токен | Пример | Вывод |
|---|---|---|
| `YYYY` | `'2026'` | Четырёхзначный год со знаком минус для отрицательных лет. |
| `YY` | `'26'` | Двузначный год. |
| `Q` | `'4'` | Календарный квартал от 1 до 4. |
| `M`, `MM` | `'11'`, `'05'` | Номер месяца — без ведущего нуля или с дополнением до двух цифр. |
| `MMM`, `MMMM` | `'Nov'`, `'November'` | Локализованное название григорианского месяца; автоматически склоняется после токена дня, даже если между ними стоит литеральный текст. |
| `D`, `DD` | `'5'`, `'05'` | День месяца — без ведущего нуля или с дополнением до двух цифр. |
| `Do` | `'16th'` | День месяца с английскими порядковыми суффиксами, локальным маркером дня вроде `'6.'` или `'6日'` либо пользовательскими [`ordinals`](/api/configure/). |
| `DDD`, `DDDD` | `'320'`, `'045'` | День года — без ведущих нулей или с дополнением до трёх цифр. |
| `E` | `'7'` | День недели по ISO от 1 (понедельник) до 7 (воскресенье), совпадает с `dayOfWeek`. |
| `d` | `'0'` | День недели от 0 (воскресенье) до 6 (суббота), как в Moment и Day.js. |
| `dd`, `ddd`, `dddd` | `'Mo'`, `'Mon'`, `'Monday'` | Локализованное кратчайшее, сокращённое или полное название дня недели; настраивается через [`weekdayNames`](/api/configure/). |
| `W`, `WW` | `'47'`, `'05'` | Номер недели года по ISO — без ведущего нуля или с дополнением до двух цифр. |
| `H`, `HH` | `'9'`, `'09'` | Час в 24-часовом формате — без ведущего нуля или с дополнением до двух цифр. |
| `h`, `hh` | `'9'`, `'09'` | Час в 12-часовом формате от 1 до 12. |
| `m`, `mm` | `'5'`, `'05'` | Минуты — без ведущего нуля или с дополнением до двух цифр. |
| `s`, `ss` | `'8'`, `'08'` | Секунды — без ведущего нуля или с дополнением до двух цифр. |
| `S`, `SS`, `SSS` | `'4'`, `'42'`, `'420'` | Десятые, сотые доли секунды или миллисекунды. |
| `A`, `a` | `'AM'`, `'am'` | Прописные или строчные `'AM'`/`'PM'` в английском либо локальное обозначение части суток вроде `'午後'` или `'م'`. |
| `Z`, `ZZ` | `'-08:00'`, `'-0800'` | Смещение UTC с двоеточием или без него. |
| `z`, `zz` | `'PST'` | Локализованное краткое название часового пояса. |
| `zzz`, `zzzz` | `'Pacific Standard Time'` | Локализованное полное название часового пояса. |
| `X` | `'1794850200'` | Метка времени Unix в целых секундах. |
| `x` | `'1794850200000'` | Метка времени Unix в миллисекундах. |
| `[text]` | `'[at]'` | Экранированный литеральный текст, копируемый в вывод без изменений. |
:::

Нераспознанные буквы вне квадратных скобок выбрасывают ошибку [`unknownFormat`](/api/errors/#units-zones-and-formats) вместо вывода сырых символов. Токены, склеенные с буквами с диакритикой вроде `'às'`, или смешанные часовые токены вроде `'HHhmm'` тоже выбрасывают ошибку. Одиночная буква `T` проходит без экранирования для меток ISO.

Запрос поля, которого нет у типа, выбрасывает ошибку [`unsupportedToken`](/api/errors/#units-zones-and-formats) вместо подстановки фиктивной полуночи. Попытка отформатировать токены времени суток вроде `'HH:mm'` на календарной дате сразу завершится ошибкой.

Ядро также экспортирует [`monthNames()`](/api/month-names/) и парную функцию `weekdayNames()` для заголовков календаря и выпадающих списков месяцев (первый день недели в `weekdayNames()` задаётся английским названием вроде `'monday'`):

```js
import { monthNames, weekdayNames } from 'native-dates';

monthNames('short', 'en-US'); // ['Jan', 'Feb', 'Mar', ...]
weekdayNames('short', undefined, 'en-US'); // ['Sun', 'Mon', 'Tue', ...]
weekdayNames('narrow', 'monday', 'en-US'); // ['Mo', 'Tu', 'We', ...]
```

## Собственные именованные форматы

Зарегистрируйте переиспользуемые имена форматов в [`configure()`](/api/configure/), если приложение применяет один и тот же шаблон токенов или объект параметров `Intl` в разных частях интерфейса. Пользовательские имена работают для дат, времени суток, моментов времени, частичных дат и диапазонов и имеют приоритет над встроенными пресетами. Подробнее — в разделе [Именованные форматы](/guides/customization/#named-formats).

## Форматирование диапазонов

Любой [диапазон](/api/ranges/) форматирует пресеты и объекты параметров через `Intl`, автоматически сворачивая общие части месяца или года. Если передать шаблон токенов, обе границы форматируются отдельно через `' – '`:

```js
import { dateRange, timeRange } from 'native-dates';

const week = dateRange('2026-09-01', '2026-09-07');
const shift = timeRange('9:00am', '5:00pm');

week.format('medium', 'en-US'); // 'Sep 1 – 7, 2026'
week.format('YYYY-MM-DD'); // '2026-09-01 – 2026-09-07'
shift.format('short', 'en-US'); // '9:00 AM – 5:00 PM'
```

## Относительные фразы

Вызовите [`from()`](/api/date-time/#from) или [`fromNow()`](/api/date-time/#fromnow) на моменте времени или календарной дате, чтобы получить локализованную относительную фразу через встроенный форматтер платформы. В качестве псевдонима также доступен [`formatRelative()`](/api/date-time/#formatrelative):

```js
import { date, datetime, now, today } from 'native-dates';

now().minus(5, 'minutes').fromNow('en-US'); // '5 minutes ago'
today().plus(1, 'day').fromNow('en-US'); // 'tomorrow'

const anchor = datetime('2026-11-16T12:00', 'UTC');
anchor.minus(3, 'hours').from(anchor, 'en-US'); // '3 hours ago'
anchor.minus(23, 'hours').from(anchor, 'en-US'); // '1 day ago'

const currentDay = date('2026-11-16');
currentDay.minus(1, 'day').from(currentDay, 'en-US'); // 'yesterday'
currentDay.plus(14, 'days').from(currentDay, 'en-US'); // 'in 2 weeks'
```

Календарные даты считаются в целых днях, поэтому `from()` и `fromNow()` в пределах семи дней возвращают слова вроде «вчера», «сегодня» и «завтра». Моменты времени измеряют прошедшее по часам время и после `'now'` используют числовые формулировки, ведь 23 часа назад могли приходиться ещё на тот же календарный день.

Далее прочитайте руководство [Разбор](/guides/parsing/), чтобы узнать, как преобразовывать входящие строки и внешние значения обратно в объекты.
